# Macro Check — notes for Claude

Phone web app (GitHub Pages, `main` branch root) for judging supermarket foods by macros and price.
Full user and technical documentation: README.md. Read it before changing behaviour.

## Conventions
- No build step and no frameworks: plain `index.html` (UI) + `core.js` (all calculations, DOM-free).
  Put new calculations in `core.js` and cover them in `tests/unit.js` with hand-checked numbers.
- Every app change: bump the release number in FOUR places together: `VERSION` in `sw.js`, `core.js?v=N` in
  `sw.js` SHELL and in `index.html`'s script tag, and the "Macro Check vN" text in Settings (`tests/release.js` fails
  otherwise). Then `npm test`, README (features + changelog), push to `main`.
- Dates shown to the user are dd/mm/yyyy (`MC.dmy`).
- Free services only (Open Food Facts, Open Prices); no paid APIs, no API keys.
- User data lives only in the phone's localStorage. Never break existing stored items:
  new fields need sensible defaults for old items (see `ensureHistory`, `isProtected`).
- Values the user typed are never overwritten by lookups/rescans (`prod.edited`, `prod.tracked`).
- Commit author email must be the GitHub noreply address
  `317667440+DynamicUnicorn@users.noreply.github.com` (email privacy blocks other addresses).
- Show the user's alias via `MC.displayName(p)`, never `p.name` directly.

## Catalogue
`catalog/catalog.json` is generated by `scripts/build-catalog.js` via `.github/workflows/catalog.yml` (weekly + manual).
Never edit it by hand. Start a rebuild with:
`gh api -X POST repos/DynamicUnicorn/macro-check/actions/workflows/catalog.yml/dispatches -f ref=main`.
Open Food Facts can't be reached from Claude's workspace; GitHub Actions can. The data is ODbL: keep the attribution.

## Filling in prices (user asks "fill in prices")
Data lives in the PRIVATE repo `DynamicUnicorn/macro-check-data`, file `library.json` (`products` map keyed by id).
1. Pull the latest `library.json`. Work only on items without a price (or ones the user names).
2. Look up each item on ah.nl (fallback: jumbo.com) by alias/name/brand/pack size. AH pages show no barcode,
   so match carefully. Use the REGULAR shelf price, not a temporary bonus price.
3. Edit ONLY `price`, `priceDate` (today, dd/mm/yyyy), `priceSource` ("ah.nl" / "jumbo.com") and append
   `{price, date, source}` to `priceHistory`. Never touch other fields: the phone overwrites them anyway.
4. Unsure match (variant, size, not sold) → leave the price empty and list it for the user.
5. Commit with the noreply email, push, then give the user a review table: their name → matched product → price.
Never put the data file, targets or tokens in the public `macro-check` repo.
